# Control Plane 4.1.1

Drift schedules can retain a deleted Environment without blocking later edits.
Explicit observation target queries identify missing UUIDs separately from
inactive Environments. Grant updates can prune only exact previously granted
targets that have since been deleted, and retain that outcome in the command
receipt. A new unavailable target receives a definitive rejection before any
grant change commits.

An unstarted observation for a deleted target can close safely with
`reason: deleted_target`. Accepted work keeps its actual outcome, and completed
responses replay unchanged. The additive shared SDK is published as `3.5.0`.
The matching Drift Detection plugin requires
`environment-observation-deletion/v1`; upgrade Core before that plugin.

Database schema `57` fences the new persisted response format. Take and verify
a coordinated recovery point before upgrading. Once deletion-aware responses
exist, rollback requires restoring that recovery point with its matching
components. Do not run an older Core image against the migrated database or
delete response metadata to force a downgrade.

This release does not create Drift baselines or enable Runner observation
capacity. Those remain explicit workload configuration and deployment actions.
