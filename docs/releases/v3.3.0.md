# CP v3.3.0

Environment observation authority and Runner capacity.

## Changes

- Add optional generated Environment observation and recovery APIs while
  preserving existing mandatory shared interfaces. Use public CP shared/v3 v3.2.0,
  DP shared/v3 v3.1.0 and IAM shared v1.3.0 without local replacements.
- Enforce current canonical organization Admin membership for plugin operations
  that declare Admin policy. Granular permissions alone do not confer Admin.
- Add optional max_parallel_jobs and supported_protocols Runner settings. Omission
  preserves legacy unlimited capacity and existing protocol behavior. A positive
  configured limit bounds all jobs sharing a Runner; lowering it drains current
  work before new admission. Declare only protocols supported by the actual Runner.
- Preserve ordinary authorization, lifecycle, Module Version Pin and exact
  baseline checks for explicit corrective deployments. Durable request identities
  and receipt/seal recovery reconcile lost acknowledgements without new effects.
- Preserve entitlement fencing through service callbacks without recursively
  acquiring the same authority lock. Observation grants confer no apply authority.
- Persist canonical deletion options on each Environment lifecycle. DELETE retries
  merge flags monotonically, so accepted force or rule removal cannot be undone.
  New and replayed ordinary Destroy admissions lock that row and require a known
  non-force policy. Already authorized work may still finish after escalation.
- Fence final deletion by the expected Environment UUID and use canonical rule
  removal policy, preventing stale work from deleting a recreated same-name
  Environment. Reject stale status updates that interrupt force deletion.
- Correct outcome-acknowledgement API documentation for retained ordinary capacity
  and older ownership; this does not broaden the Data Plane's eligibility checks.

## Upgrade and recovery

The coordinated CP upgrade advances database schema51 to54, including migrations52,53
and54. Back up affected databases, role/ACL/sequence state and deployment state;
stop incompatible writers and use the qualified IAM/CP/DP/Runner artifact set.
IAM's canonical-role migration must be available before enabling requiring policy.

Migration54 leaves legacy deletion policy NULL, with no false backfill. Repeat
an explicit supported DELETE to establish policy before new Destroy or finalizing
an already deleting/delete_failed Environment. The trusted legacy unbound
internal force-delete escape hatch remains available for active Environments.
The new Data Plane binds final deletion to the lifecycle UUID. Do not roll back
to incompatible writers or discard accepted policy; recovery is forward only.
The application uses the published additive CP shared SDK3.2.0 without local
replacements. SDK3.1.0 and earlier candidate identities remain immutable.
Private plugins, their grants and licences remain separately managed.

Observations use a normal refreshed read-only plan and never apply or persist
refreshed state. Baselines use retained immutable ordinary-deployment material.
Captured inline source or an executable Git selector pinned to a full commit can
qualify without an artifact digest; supplied digests still must match. A separate
revision label does not freeze a mutable source URL.

Preserve authoritative receipts across restart and uncertain delivery. Do not
infer completion or release capacity from elapsed time. Use verified restore and
forward recovery; an older binary or Helm rollback does not reverse migrated
journals or safely restore earlier authority. Plugins remain separately installed
and licensed; absence does not enroll targets or schedule observations.

## Release security scope

The producer uses ORAS1.3.4 and Cosign3.1.3. The upstream recheck also covered
ORAS1.3.6 and Cosign3.1.4; no qualified replacement was selected for this train.
The coordinated release records explicit, release-scoped acceptance of known
residual advisories in the selected ORAS1.3.4, Cosign3.1.3 and the Runner's official
bundled OpenTofu1.13.2. This acceptance applies only to this
release and those vendor artifacts. Component source and executable checks remain
strict; it does not suppress findings in this component or replace the final
artifact/provenance checks.

Artifact printable-input scans use private regular-file stdin so scanner fragments
do not depend on pipe writes. A narrowly verified noncredential exception binds
four adjacent public dependency literals to Go 1.26.10, exact module versions and
checksums, complete literal context and exact finding hashes. Other findings and
changed metadata or context remain refusals; vulnerability checks are unchanged.

The original hosted refusal retained no raw finding identity. The classification
was reproduced locally against byte-identical hosted executable payloads.
