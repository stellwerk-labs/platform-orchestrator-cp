# Control Plane v3.2.0-rc.1

This prerelease is for evaluation with the matching Data Plane, IAM, Runner,
clients, Console and gateway routes. It is a candidate, not a completed
coordinated release. Use the final qualified compatible chart set when it
becomes available; do not mix this image with an older route or server set.

## Module authoring and interfaces

Module Drafts separate editing from publication. An author can save several
revisions under one intended SemVer, inspect them, capture an immutable scoped
test snapshot and explicitly deploy that snapshot through the normal Runner.
Saving a Draft neither runs a deployment nor reserves the version. Editing does
not change earlier captures, queued work or retained deployments. Two A/B
captures remain distinct even under the same intended SemVer.

Publication closes the Draft and creates a separate immutable Proposed Version
from the exact stored revision. Promotion remains explicit; existing Proposed,
Default and historical Versions remain immutable. Pins remain authoritative.
A Module without a Default can be tested through a Rule scoped to both Project
and Environment. Admission rechecks authoring and scoped deployment authority.

Resource Types gain immutable interface versions. Historical global and
organization-specific contracts become version 1 with their original content
and timestamps; existing Module Versions keep their exact binding. Publishing
a later interface does not move them. Older HTTP callers that omit an interface
version continue to select version 1. Existing published HTTP operations remain
available; the new authoring and test routes require matching servers and
gateway configuration. Clients must report an unsupported route rather than
silently substitute a published Default.

## Go SDK and release controls

The separately published Control Plane shared Go SDK uses the new
github.com/stellwerk-labs/platform-orchestrator-cp/shared/v3 import path. Its
generated client interfaces gain methods, so Go implementers and positional
model literals must migrate. This Go major-version change is distinct from
compatibility of existing HTTP routes. The application image tag does not
publish the nested SDK module.

The release-content path now refuses a declared SDK without an exact Git source
commit, module checksum and byte-verified licence provenance. This is a
publication control correction, not a server API change.

## Upgrade and recovery

CP migrations 49, 50 and 51 retain interface versions, Draft revisions and
test snapshots. Upgrade the compatible Data Plane before enabling these Control
Plane workflows, then update Console and clients with the matching routes.
Back up the databases, configuration and outstanding work first. Older CP/DP
binaries refuse the new schemas; do not use an old-binary Helm downgrade as
recovery. Use schema-compatible images or a forward fix. A database restore is
a separate recovery operation with its own point-in-time tradeoff.

Source-built native execution covered Draft A/B capture, queued admission,
retained rollback, normal teardown and seeded cross-service upgrade/restart.
Final packaged images, upgrade/recovery, plugin compatibility and the complete
public chart set remain qualification gates. This candidate note does not claim
those checks have passed.
