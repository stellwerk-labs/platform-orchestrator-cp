# Control Plane v4.0.0

Breaking change: Provider DELETE accepts retirement with HTTP 202. The Provider
remains readable with `deletion_requested_at` until conservative reconciliation
proves that no retained managed state needs it; physical collection then makes
GET return 404. Clients must wait for that outcome and retain historical Provider
material for cleanup instead of treating acceptance as immediate disappearance.
The generated mandatory shared client interface remains compatible; the optional
retirement metadata is published in CP shared/v3 v3.3.0.

Provider retirement is disabled by default. Upgrade every Control Plane and
Data Plane writer before enabling `PROVIDER_RETIREMENT_ENABLED`. Before activation,
DELETE returns 503. Missing, incomplete, busy or incompatible Data Plane usage
proofs leave retirement pending. Lifecycle epochs and canonical Environment
identities fence stale proofs and recreated resources.

Installation maintenance mirrors the Data Plane's revision inside committing
transactions, fences new plugin effects and reports Runner, admission, dispatch
and served-plugin pause evidence. Missing or incompatible reports prevent
`ready`; overlapping counts must not be summed. Package registration, upgrade
staging and exact-identity activation remain available during maintenance. Other
Plugin Manager mutations pause, and upgrading a disabled installation keeps it
disabled. Maintenance is an admission/drain boundary, not proof that services
have stopped or that a database backup is recoverable.

Upgrade and recovery: back up affected databases and retained deployment state.
Migrations 55 and 56 advance schema 54 to 56. Upgrade IAM 2.7.0 and the coordinated
CP 4.0.0/DP 4.3.0, Console and Core Helm set before enabling their new settings and
retirement controls. Keep retirement disabled until all writers are upgraded.
Pending deletion requests and an active maintenance barrier deliberately refuse
unsafe down migration. Preserve authoritative receipts, verified backups and
restore/forward recovery; an older image or Helm rollback does not reverse the
accepted authority or journals.

Security: builds use Go 1.26.11 and retain source/executable/content, original OCI,
SBOM, provenance, reproducibility and signature gates. Root modules consume the
published CP shared/v3 v3.3.0, DP shared/v3 v3.2.0 and IAM shared v1.3.0 without
workspace or sibling-directory replacements.
