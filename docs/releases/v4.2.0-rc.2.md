# Control Plane 4.2.0-rc.2

Project pipelines give teams a shared deployment contract across the Console designer, JSON and YAML documents, API, octl and Terraform/OpenTofu Provider. Draft editing, immutable publication and project policy are separate operations, with revision checks that reject conflicting edits and stale publication requests.

Deployments apply directly by default. A Plan runs when explicitly requested or when a reviewed pipeline requires it. Published recipes can choose direct Apply or Plan with approval, and attach supported, catalogue-validated steps before Plan, to check Plan, or after Apply. Reviewed recipes can request cost estimation and conditional approval when the supported cost comparison proves no increase. Missing or incomplete evidence does not grant automatic approval.

Project policy can restrict eligible published versions and set independent forward and rollback defaults, including environment-specific choices. An explicit version remains subject to policy and Runner compatibility at admission; clients cannot supply an executable recipe to bypass those checks.

Native Agent registration uses an immutable server-issued UUID and an approved execution catalogue. Registration alone does not activate or assign a site. Existing registration history is retained, and clearing its inventory disables new admission without cancelling accepted work.

Use matching IAM pipeline permissions and the coordinated Data Plane, Runner and client candidates. Recipes use Stellwerk's supported step contract; they do not accept uploaded Temporal or DBOS workflow programs. Native production activation requires the documented PostgreSQL, retained-key, trust, state-backend and recovery profile.
