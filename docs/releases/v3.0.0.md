# Control Plane v3.0.0

This release introduces Module Version Management in the Orchestrator.
It changes Module authoring and the public API contract. Test the upgrade and
your publishing automation before adopting the coordinated release.

## What changes

- Modules retain a stable catalogue identity; executable definitions are complete,
  immutable SemVer versions with their own UUIDs.
- Publication creates a Proposed version. Promotion explicitly selects a stable
  Default. Deprecated and Defective versions have restricted use, and restoration
  is limited to the exact eligible predecessor of a Defective Default.
- History, structural before/after comparison and adoption queries expose the
  versions that actually ran. Archival preserves published versions and audit history.
- Exact Environment version Pins support scoped control, atomic bulk operations
  over frozen Environment IDs and append-only notes. Pinning does not deploy.
- Resource Types are immutable interfaces. Optional module contracts validate
  declarations offline; new versions must explicitly declare the exact output
  schema of a Resource Type whose output schema is nonempty.
- Lifecycle and Pin commands use idempotency, optimistic concurrency and retained
  audit events. Existing role grants map only to their equivalent permissions.

## Breaking changes and upgrade actions

1. Upgrade the compatible server, Runner and clients together. Older writers
   cannot keep mutating executable Module definitions or Resource Type contracts.
2. Replace mutable authoring with catalogue creation, complete version publication
   and explicit promotion. Published SemVers and definitions cannot be overwritten.
3. Supply an exact source revision for external Terraform/OpenTofu sources.
   An artifact digest is **optional**. If supplied, it must be a valid immutable
   claim; omit an unknown digest rather than submitting an empty or invented one.
   Inline sources must omit it. Neither a digest nor successful publication is
   trusted artifact verification; versions remain Unverified.
4. Supply required output declarations. Historical absence remains historical
   absence, not an inferred schema or verification claim.
5. Review granular permissions before reopening automation. New powers such as
   Defective marking, restoration and Pin control are not added to legacy grants.
6. Go consumers using the new DTOs must import
   `github.com/stellwerk-labs/platform-orchestrator-cp/shared/v2`.
   Its separate release tag is `shared/v2.0.0`; the root application tag
   does not publish that module. Existing v1 source remains available unchanged.
   The new shared module requires Go 1.26.2.

## Data, migration and recovery

Back up databases, encryption/key storage, deployment configuration and
Terraform/OpenTofu state before upgrading. Drain active Deployments and prevent
legacy and managed writers from running concurrently.

The release adds Control Plane migrations 24 (Module Versions and Pins),
25 (extension contracts) and 26 (Resource Type contracts and output declarations).
Apply them through the supported migration path, not by editing live rows.

Migration preserves the old Default's opaque identity as legacy generation v0.
It does not invent SemVers, digests or output declarations. Existing Deployment
snapshots remain readable. The first managed version is a separate publication;
v0/v1 generation markers are not values to submit as semantic versions.

Published versions and audit history survive teardown. Archive retained Modules
and explicitly retain their referenced dependencies; do not expect a clean
catalogue after infrastructure destruction.

After new Module or Pin writes, recover with a compatible application revision
or forward repair. Dropping new tables or declaration columns is not a safe
application rollback and can destroy retained history.

## Compatible release set

Use CP 3.0.0, DP 3.2.0, IAM 2.4.0, Runner 3.1.0,
Console 1.3.0, CLI 2.0.0 and Terraform/OpenTofu provider 2.0.0.
The coordinated chart is 0.7.0. Keep its complete component set together when
upgrading; an individual image update does not migrate authoring clients.
